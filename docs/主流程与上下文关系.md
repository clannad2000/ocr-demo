# 主流程与上下文关系

## 自动书籍上下文

统一入口首先读取`config/pipeline.json`。当`pdf`是文件时处理一本书；当它是目录时，
按文件名排序处理目录直属的全部PDF。每本书独立生成：

```text
runs/book/<slug>/
├── 01-ocr/
├── 02-codex-review/
├── 03-final/
├── 04-erased/
└── 05-pdf/
```

后续阶段不从配置读取输出路径，而是根据同一个PDF的slug取得前一阶段产物。因此不会
把不同书籍的页面、检查点、裁决或PDF混在一起。

## 阶段1：OCR、OCR复核和DeepL翻译

```powershell
python -m pipeline ocr
```

输入是源PDF和配置中的`pages`。同一渲染页并行进入DeepSeek版面定位与Qwen主OCR；
确定性风险检查决定`verify: auto`是否调用图像OCR复核。主OCR选出的学习区域随后由
DeepL逐区域翻译。

写入`01-ocr`：

- `pages/page-NNNN.png`和`pages/page-NNNN.json`；
- `manifest.json`、`summary.md`、`study.html`；
- `info.log`。

页面JSON是后续流程的不可变机器证据。

## 阶段2：Codex整书翻译复核

```powershell
python -m pipeline review
```

若`02-codex-review/book-review-plan.json`不存在，入口先读取配置中的`toc_pages`并调用
计划阶段；随后按计划读取`01-ocr/pages`。前置内容和每个正式章节分别使用可恢复的
持久Codex任务。

写入`02-codex-review`：

- `book-review-plan.json`；
- `book-review-checkpoint.json`；
- `book-codex-review-summary.json`；
- `chapters/<task-id>/page-NNNN-codex-review.json`。

Codex结果不写回页面JSON、`manifest.json`或`study.html`。

## 阶段3：生成最终裁决文件

```powershell
python -m pipeline finalize
```

定稿器汇合`01-ocr`页面证据和`02-codex-review`裁决，验证源PDF、输入SHA-256、全部
`page + region id`、章节任务一致性及未解决人工项。

写入`03-final`：

- `book-codex-adjudication.json`；
- `chapter_translation_final.json`；
- `pdf_backfill_plan.json`。

若`config/overrides/<slug>.translations.json`存在，定稿器自动读取；原页面记录保持
不变。锁定快照是PDF阶段唯一译文来源。

## 阶段4：擦除英文

```powershell
python -m pipeline erase --dilate-iterations 2
```

入口自动把`01-ocr/pages`作为批量输入，把`04-erased`作为输出。每张PNG必须存在同名
页面JSON。擦除器使用DeepSeek坐标、字形掩码和OpenCV局部修复生成cleaned PNG、
mask、debug图和adjusted JSON；它不写中文。

## 阶段5：写入中文PDF

```powershell
python -m pipeline write
```

写入器自动汇合：

- 源PDF；
- `03-final/chapter_translation_final.json`；
- `03-final/pdf_backfill_plan.json`；
- `04-erased/page-NNNN.cleaned.png`；
- `pdf_writer.rules`；
- 可选`config/overrides/<slug>.layout.json`。

写入`05-pdf/<slug>-zh-review.pdf`和程序检查报告。写入器不执行擦除、不改变译文。

## 产物映射

| 产物 | 直接来源 | 消费者 |
|---|---|---|
| 页面JSON | OCR、OCR复核、DeepL | Codex复核、定稿、擦除 |
| 复核计划 | 目录页、PDF页数、Codex | 分章复核、定稿 |
| 独立Codex裁决 | 页面区域、章节上下文、必要图片 | 定稿器 |
| 锁定译文快照 | 页面译文、Codex裁决、可选人工覆盖 | PDF写入器 |
| 坐标计划 | 锁定译文、DeepSeek坐标 | PDF写入器 |
| cleaned PNG | 页面图、DeepSeek坐标 | PDF写入器 |
| 中文PDF | 源PDF、快照、坐标计划、cleaned PNG | 人工视觉验收 |

## 运行纪律

- `ocr`、`review`、`finalize`和`write`可先加`--dry-run`；
- 真实OCR、DeepL、Codex与批处理由用户运行；
- 程序全量检查、可选AI抽查和人工视觉验收必须明确区分；
- `program_checked`不代表视觉验收通过。
